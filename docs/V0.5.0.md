# Settle Backend v0.5.0

## Financial core

The database is the source of truth for local financial state. PayPal is an external payment rail.

### Invoice lifecycle

```text
draft -> sent -> paid -> refunded
   \-> cancelled
sent -> cancelled
```

Illegal transitions are rejected.

### Payments

Payments are workspace-scoped and linked to invoices. A successful payment marks its invoice paid; a refunded payment marks the invoice refunded. Provider IDs are unique per provider.

### Idempotency

Financial create operations can accept an `Idempotency-Key`. The request body is hashed and a completed response is replayed for an identical request. Reusing a key with a different body is rejected.

### Transactional outbox

Financial writes and their durable asynchronous events are committed in the same PostgreSQL transaction. A worker dispatches pending outbox events to BullMQ and processes provider side effects with retry/backoff.

### Webhook reconciliation

PayPal webhooks are signature verified, persisted before asynchronous processing, deduplicated by provider event ID, and reconciled against local invoices/payments.

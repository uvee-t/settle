# Settle v0.7.0 — Document Verification

## Upload flow

1. Client computes SHA-256 and size.
2. `POST /v1/documents/upload-url` validates content type and size and returns a short-lived S3 PUT URL.
3. Client uploads directly to the workspace-scoped private S3 key using the required checksum/content headers.
4. `POST /v1/documents` verifies the object exists, size, content type and S3 checksum before creating the database record.
5. BullMQ schedules asynchronous verification.
6. The worker downloads the object, recomputes SHA-256, validates magic bytes/extension, and optionally scans the content with ClamAV.
7. The document becomes `verified` only after all checks pass. Failed validation becomes `rejected`; infrastructure/scanner failures are retried.

## Statuses

- `pending`: verification queued or requested
- `verifying`: worker is actively verifying
- `verified`: integrity/type/security checks passed
- `rejected`: verification failed

## Production requirement

Set `DOCUMENT_MALWARE_SCAN_ENABLED=true` in production and provide a reachable ClamAV daemon. Production startup rejects configurations that disable malware scanning.

# Settle v0.12.0 — Concurrency and Recovery Hardening

## Purpose
Harden external side effects and AI execution against concurrent requests, worker retries, and crashes between provider calls and local persistence.

## Changes
- Added a Redis-backed distributed lock utility with token-safe release.
- Dispute defense AI runs are locked by workspace + input hash and re-check successful runs after lock acquisition, preventing concurrent duplicate provider calls.
- Evidence submissions are locked by dispute + evidence type.
- Evidence submissions now use a local `SUBMITTING` state while the PayPal side effect is in progress.
- Existing provider evidence is checked before a new PayPal submission, allowing recovery after a process crash between the provider call and local persistence.
- Existing submitted evidence rows remain idempotent and self-heal a missing evidence request ID.
- Evidence-pack submission audit metadata now records concrete submission IDs and evidence types.
- Added `.env.example`; real `.env` files must remain local and uncommitted.

## Safety
- Redis lock release is token-checked so one worker cannot release another worker's lock.
- PayPal POST retries remain disabled unless the request is explicitly safe to retry.
- Provider state is reconciled before retrying an interrupted evidence submission.

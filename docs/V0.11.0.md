# Settle v0.11.0 — Dispute Transaction Reconciliation

## Purpose
Persist the deterministic relationship between a PayPal dispute and the Settle payment/invoice that caused it.

## Safety rule
Reconciliation accepts only exact provider identifiers or an exact identifier contained in a durable provider payload. It never matches disputes to financial records using amount, currency, dates, names, or other fuzzy heuristics.

## Changes
- `disputes.payment_id` links to the Settle payment when resolved.
- `disputes.invoice_id` links to the Settle invoice when resolved.
- Direct match: PayPal seller transaction ID == `payments.provider_payment_id`.
- Fallback: exact seller transaction ID found inside a stored payment provider payload.
- Fallback: exact seller transaction ID found inside stored invoice provider payloads.
- Evidence collection prefers persisted dispute payment/invoice links.
- Only accepted milestone deliveries are emitted as fulfillment evidence candidates.
- PayPal response deadline accepts `seller_response_due_date` or `buyer_response_due_date`.
- Seller-protection fields are read from the disputed transaction when PayPal returns them there.

## Important E2E note
An unrelated manually-created PayPal dispute will remain unlinked if its provider transaction cannot be found in Settle. This is intentional. Do not create a false financial relationship merely to make an evidence pack appear populated.

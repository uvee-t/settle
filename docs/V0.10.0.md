# Settle v0.10.0 — Delivery & Acceptance Evidence

This release adds a deterministic delivery/acceptance layer between milestones and dispute evidence.

## New data model

- `milestone_deliveries`: immutable-ish delivery lifecycle (`SUBMITTED`, `ACCEPTED`, `REJECTED`)
- `milestone_delivery_documents`: verified S3 documents attached to a delivery
- `milestone_acceptance_events`: append-only acceptance/rejection history
- one accepted delivery per milestone is enforced by a PostgreSQL partial unique index

## API

- `GET /v1/milestones/:id/deliveries`
- `POST /v1/milestones/:id/deliveries`
- `GET /v1/deliveries/:id`
- `POST /v1/deliveries/:id/accept`
- `POST /v1/deliveries/:id/reject`

A delivery document must already be verified. Rejection requires a reason. Accepted deliveries cannot be transitioned again.

## Evidence integration

Evidence collection now includes accepted/submitted/rejected milestone deliveries and verified documents attached to them. Accepted delivery evidence receives the highest deterministic confidence and can satisfy `PROOF_OF_FULFILLMENT` / `PROOF_OF_DELIVERY` requirements.

## Migration

Run:

```bash
npm run db:migrate
```

The migration is `drizzle/0010_delivery_acceptance.sql`.

Then:

```bash
npm run build
```

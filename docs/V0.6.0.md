# Settle Backend v0.6.0

## Production hardening

- PayPal webhooks now use a transactional DB outbox before entering BullMQ.
- Duplicate PayPal webhook deliveries are idempotent and can be recovered by the worker.
- Webhook processing retries transient failures without falsely marking the event permanently failed on the first attempt.
- Startup/background recovery recreates missing webhook delivery instructions for received events.
- BullMQ job IDs are deterministic and never contain `:`.
- JWT signature, malformed-token, and expiry errors return `401` instead of leaking provider exceptions as `500`.
- Production environment validation prevents sandbox PayPal usage and default localhost CORS.
- PayPal requests retry only when safe to retry; idempotent POSTs can retry when `PayPal-Request-Id` is present.
- Workspace IDs are validated as UUIDs before database access.
- Manual invoice transitions cannot force `paid` or `refunded`; provider payment events own those financial states.
- Payment status transitions are guarded.
- Disputes can infer their workspace from the related payment/invoice transaction.
- Evidence packs are scoped to the disputed invoice/payment/contract instead of returning unrelated workspace records.
- Duplicate evidence submissions are prevented.
- S3 uploads require SHA-256 checksum signing and finalization validates S3's checksum when returned.
- S3 object keys are workspace-scoped for both upload finalization and download URLs.
- Cash-flow forecasting is available by currency.
- Automated invoice reminders are queued with per-invoice/day idempotency.
- Dashboard aggregation no longer mixes currencies.
- Sensitive request/provider payloads are redacted from structured logs.
